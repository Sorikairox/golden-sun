# G14 field notes (session GS14, 2026-11-02): code-range audit; Sol Sanctum to the Elemental Star Room

## 1. Code-range audit (traps 26, 40, 41)

In wasm a code "address" is a function-table index (0x10000-0x1ffff), so vendor C that classifies a value as code or data
by its range or high bits, or measures code by subtracting addresses, behaves differently in the port.

- `tools/wasm/code_range_audit.py` scans the pinned vendor tree (`games/tbs/src` and `include`, `.c`/`.h`, comments and
  strings removed) for six pattern ids: `shr24` (`>> 24..27`), `topmask` (0x0f000000, 0xff000000, 0xf0000000, 0x0e000000),
  `region` (0x02/03/06/08/09000000, 0x02040000, 0x03008000, 0x02008000, 0x02010000), `below64k` (comparisons with
  65536/0x10000/0xffff), `msgend` (TRIGGER_RESULT_MESSAGE_END, FIND_FUNCTION_BITS, IWRAM_START, EWRAM_END), `codediff`
  (`(u32)a - (u32)b`).
- `port/tools/code_range_audit.tsv`: one row per hit (file, line, pattern id, verdict, why; no code text). 46 hits: 29 data,
  8 safe (message-id tests below 65536 = trap 26; sprite_draw.c's code length), 7 fixed, 2 replaced (flash.c).
- Build guard: `tools/wasm/build.py` runs it as the first stage (`audit`); a hit with no row (a re-pin, a new pattern) or a
  stale row fails the build. Negative control: dropping the task.c:287 row -> "NEW unaudited ... FAIL".
- Other sweeps with no hit worth a row: Thumb-bit manipulation of code pointers, pointer-range compares against
  gOverlayArea/Rom_Start, comparisons with mid-range constants, the asm sources (ported routines) and port/pc itself.

**Real bug fixed**: `system/system/task.c` Task_SuspendOverlayTasks / Task_ResumeOverlayTasks pick scene-overlay tasks by
`(task->func >> 24) == 2` (overlays run from EWRAM). A wasm routine never matched, so opening a menu never suspended the
scene's tasks (World Map tasks, the Luna/Sol falling lights, the statue room's clouds, the eruption's embers...). c_rules.tsv
now also accepts `Port_CodeIsOverlay(task->func)` (codemap.c: the index is one of the overlays' code-map rows). All 19 old
regress digests unchanged: no tested path had an overlay task while a menu opened (a temporary probe on sol_jewels and
worldmap saw only main-image task routines). On-screen confirmation under a menu was not conclusive (statue-room sky crops).

**Tried and reverted**: sprite_draw.c:66 `(u32)gRender_DecodePictureEnd - (u32)Render_DecodePicture` looked like a
code-address difference, but bind.py binds asm routines declared as data to their ROM address (build/wasm/code_as_data.tsv),
so the length was already right; a Port_CodeGbaOf rule turned it into a corrupt DMA count and crashed (TrackStop, regress
STOPPED). Lesson in trap 41: check code_as_data.tsv first.
