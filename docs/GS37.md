## What the player does

signed in: the account's GS1 save is pulled first): New Game, Felix named, "Transfer data from Golden Sun?" -> **Yes**.

the imported party. With no Golden Sun save (or no cleared file) the cartridge's menus appear unchanged.

## How

- **retrowser** (~/Code/retrowser 665f135, deployed 2026-11-12, Worker 147d9fec): manifest `saveFrom: [{ dir }]`
  names other games of the same repository; at start the host copies that game's save on this device to the module's
  `rtw_save_from(index, size)` before `rtw_start` (spec 4.11).
- **TLA's manifest** (port/rtw/tla.retrowser.json): `"saveFrom": [{ "dir": "" }]` (GS1's retrowser.json is at the root).
- **port/rtw/rtw_tla_party.c** (rtw.c, TLA only): takes the 64 KB image, picks the cleared file with the longest play
  time (the earlier on a tie) and builds the 4,100 bytes GS1's cable send puts on the wire, directly from the flash
  sectors (the same choice as GS1's Save_InitializeWork / Save_FindLatestSector / Save_LoadFileSummaries /
  Save_ReadPart: no second module, unlike the page's transfer.js). Then Port_TlaAutoTransferArm(1) (TLA9's hook).
- **port/rtw/rtw_glue.js**: once the Transfer Method menu answered Link cable, a virtual Golden Sun (transfer.js's
  VirtualGs1, the same exchange) is Module.linkTransport and sends the bytes; 600 frames after TLA took them it
  leaves, armed again.
- tools/wasm/link.py RTW_TLA_EXPORTS: rtw_save_from, port_rtw_party(_info), Port_TlaAutoTransferHits/Arm.
