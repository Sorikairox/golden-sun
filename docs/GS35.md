# GS35 — 2026-11-08: Ivan never learned Reveal from Hama

User: "I talked to the master in Lama to get reveal, but Ivan doesn't have the skill".

## Cause

Hama's lesson in Lama Temple (scene/fuchin_temple.c FuchinTemple_RunHamasRevealLesson) ends with
`Party_LearnAbility(IVAN, ABILITY_REVEAL)` (field/event_commands/event.c). That routine calls the K&R-declared far
veneer `Unit_LearnPsynergyFar()` with no arguments: on the ARM, unit and ability are still in r0-r1 from its own
call. In wasm the K&R adapter passes 0 for missing words (trap 75), so the game ran Unit_LearnPsynergy(0, 0), which
changes nothing, then played the jingle and showed "Ivan learned Reveal!". Party_LearnAbility has no other caller in
GS1, so Reveal was the only Psynergy lost this way.

The build check for this class (tools/wasm/short_knr.py, TLA7) only ran on The Lost Age. Run on GS1 it listed exactly
this call: `Unit_LearnPsynergyFar$ci32_ passes 0 of Unit_LearnPsynergyFar's 2 words`.

## Fix

- port/c_rules.tsv: `Unit_LearnPsynergyFar();` -> `Unit_LearnPsynergyFar(unit, ability);` (what r0-r1 hold).
- Saves made before the fix: the scene sets FLAG_XIAN_HEARD_HSU_TRAPPED (0x895) after teaching, and on the GBA
  nothing removes Reveal afterwards. Port_RepairRevealLesson (port/pc/save_compat.c), called at FieldSequence_Run's
  start (the existing GS27 rule), teaches Ivan (unit 2) Reveal (ability 144) when the flag is set and he lacks it. A
  no-op for every other game.
- tools/wasm/build.py: the short K&R check is its own stage `knr`, run for both games; GS1's allow list is
  port/short_knr_allow.tsv (empty). GS1 now: 0 adapters drop words; TLA unchanged (5 allowed).
