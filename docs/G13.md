## 3. Port bug found and fixed: examine events ran as locked chests (trap 40)

Searching the first minotaur relief showed "but Isaac can't open it..." (MsgCantOpenIt) instead of the relief's
message, and the jewel could never be set. Field_ExamineCell (field/field_sequence/triggers.c) tells an event routine
from a search result by bits 27-24 of the trigger's value (FIND_FUNCTION_BITS 0x0f000000, set in every GBA code
address 0x02.../0x08...). In the wasm build the value is a function-table index (0x10000-0x1ffff, trap 26) with none
of those bits, so every EXAMINE_TRIGGER(...) whose value is EVENT(...) went down the chest path, and bits 19-16 = 1
read as FIND_CHEST_LOCKED. Every FIND_ value is >= 0x100000, so the index range is unambiguous: a port/c_rules.tsv
text rule makes the test `(searchResult & FIND_FUNCTION_BITS) != 0 || PORT_IS_CODE_INDEX(searchResult)`
(port/shim/port_api.h). No asm routine involved (vendor C), so no EQUIV spec; checked by real play (the relief's
message, the menu, the jewel set) and regress. Affected: every examine trigger whose value is an EVENT(...) routine in any scene (both reliefs, Sol Entrance's locked
door after the eruption...); chests, coins, Psynergy Stones and FIND_MESSAGE triggers are FIND_ values and were fine.

Other pointer-bit tests in vendor C (searched `>> 24`, `0x0f000000`, `0x08000000` compares): system/system/task.c
`(task->func >> 24) == 2` (EWRAM overlay code); not met so far, left as is (worth a look if tasks misbehave).
