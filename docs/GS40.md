# GS40: TLA Djinn battles never started (session GS40, 2026-11-16)

User (iPhone, retrowser): "When encountering a djinn which wants to fight, the [fight] doesn't start"; "The djinn jump on
[us] but nothing happens and I can walk away. The djinn in the Kandorean cave for exemple".

## Cause

The Kandorean Temple's cave event 11 (overlay 0x653, events_a.c) calls Func_080d2b4c(11, 27) through its import
veneer: it queues the Djinni (pendingDjinnEvent) and sets the battle's enemy group from
Encounter_GetDjinnEnemyGroup(djinn). That vendor function has **no return statement** (the vendor marks it UB: on the
ARM the called getter's result stays in r0, so it works; the fix sits behind UBFIX, which we do not define). In wasm the
missing value was 0: enemy group 0, no battle; the Djinni's jump and the event ran, then the party walked on. Every
field Djinn battle goes through it (22 scenes import the veneer).

## Fix

port/tla/c_rules.tsv: the call becomes `return Encounter_GetEnemyGroupAtSlot(...)` (the ARM's r0, = UBFIX). The other
vendor-marked missing return, field/map/stops.c (delta 0: value in r0), returns value the same way. Trap 101.
