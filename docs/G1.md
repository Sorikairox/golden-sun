## alchemy tbs-en: matches except two compilers' output

`make bootstrap` builds four compilers. Two of them need sources that were **not** in the approval:

| compiler | used for | source | status |
|---|---|---|---|
| alchemy GCC (2.96, 2000-07-31) | all game Thumb C | alchemy-gcc | built, `generated-check` OK |
| GAS 2.10 | assembles the compilers' output | binutils-2.10.tar.gz | built |
| old_agbcc | sound library (`audio.c`, `driver.c`, `tables.c`), flash library (`flash.c`, `sst.c`, `atmel.c`, `program_flash_sector.c`) | `pret/agbcc` at `da598c1d`, a **nested submodule** of alchemy-gcc | **not fetched: needs approval** |
| GCC 2.95.2 ARM | `glyph_arm.c`, `actor_update_arm.c`, `world_map_lines.c` | `gcc-2.95.2.tar.gz` from ftp.gnu.org (alchemy-gcc's `arm/Makefile`) | **not fetched: needs approval** |

So the build runs with a stand-in for those two (`tools/ref/standin_cc1.sh`: alchemy GCC's own cc1 on the same
preprocessed file). Their ten objects then have the wrong code and size, and everything after them in the same
ROM bank moves. `tools/ref/standin_fix.py` recovers the original layout without reading their bytes:

1. Every exact section after a stand-in is searched for in the player's ROM near its built address (pointer
   words masked, since they move with the layout); its shift is where it matches (quality >= 0.9).
2. The stand-in sections are the gaps between those anchors. A gap's extent gives the original size; several
   stand-ins in one gap are split by **cross-reference evidence**: every Thumb BL and literal word in an anchor
   that targets a stand-in symbol is decoded again at the same place in the ROM, which gives that symbol's
   original address (47 symbols placed this way, each from 1-4 agreeing references; 0 conflicts).
3. Each stand-in object is replaced by assembly that is zero fill of the original size, with its global symbols
   at their original offsets, and the image is relinked.

Two quirks found: GCC 2.96 puts const data in `.text` where old_agbcc writes `.rodata` (so four flash objects
have `.rodata` sections in the original that the stand-in never emits; the map's `*/obj.o(.rodata)` request
lines mark where they go), and the 0x28 bytes after `flashat.o` are given to `atmel.o .rodata` rather than
`program_flash_sector.o .rodata` (both end the bank, so nothing else moves either way).

**Result** (SHA-1 of the build `63e4a8ac...`, not `5c469520...`): same size, and **every byte equal to the
player's ROM except 11,596 bytes (0.14 %)**, all inside the ten stand-in objects' own sections:

| object (section) | bytes differing |
|---|---|
| sound/audio + sound/driver (.text) | 5,522 |
| gamepak/flash/flash, sst, program_flash_sector, atmel (.text) | 2,666 |
| window/glyph_arm (.text) | 1,324 |
| field/actor_update_arm (.text) | 1,220 |
| field/world_map_lines (.text; same size, kept from the stand-in) | 644 |
| flash .rodata x4 (zero fill) | 220 |

All 96 overlay streams, every asset, the other 649 ROM sections and every address outside those objects match.
So the non-match is fully explained by "missing steps" (two compilers not built), not by the toolchain version
or the platform. With `pret/agbcc` and `gcc-2.95.2.tar.gz` approved, `tools/build_ref.sh` builds the real
compilers automatically (it checks for their sources) and should reach `compare-tbs-en: OK`.

## wasm compile census (G2 start)

`tools/wasm_census.py` (host clang 23, `--target=wasm32`, `-std=gnu89 -ffreestanding -nostdinc -DMODERN=1`):

| | syntax only | full compile to a wasm object |
|---|---|---|
| GS0 (no shims) | 68 / 394 | - |
| GS1 baseline (same flags, errors only) | 105 / 394, 105 / 166 linked | - |
| GS1 with `port/shim` | 375 / 394, **160 / 166 linked** | 373 / 394, **159 / 166 linked** |

"linked" = the 166 C objects alchemy actually links into tbs-en (the other .c files are `#include`d by them).
The shim layer (`port/shim/prelude.h`, forced first, takes over the vendor headers by their include guards):
`dma.h`, `iwram_call.h`, `transform.h`, `mul_q16.h`, plain `FIXED_ADDRESS`, and `__builtin_return_address`.
The seven linked files left all need a source-level override (`port/overrides.tsv`): GNU nested functions
(`turn.c`, `windows.c`, `battle_djinn_preview.c`, `particle_streams.c`), address arithmetic on IWRAM code
(`item.c`, `actor_update_arm.c`), and `frame.c` (Halt/Stop SWIs and the stack switch, which becomes the D8
fiber yield).
