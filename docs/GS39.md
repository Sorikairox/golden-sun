# GS39: TLA World Map objects blown up while walking (session GS39, 2026-11-16)

User (iPhone, retrowser): "There is a problem rendering villages while moving on the world map" (screenshot: Daila
drawn as a large mosaic cut off by its box); "it happens to all objects on the world map. Caves, Tower etc"; "I can
also see it on 'cinematic' in the first temple. The head of monks get the same issue with their head rotate".

## Cause

TLA's Trig_Cos was bound to GS1's C twin (port/pc/asm_small.c; bindings.tsv kind gs1, "bytes differ@8"). The two
games' trig.s differ: GS1's Trig_Sin reads a 0.16 quarter-turn table (`Trig_SineTable`) with an on-axis branch; TLA's
reads a signed 1024-entry whole-turn table placed after its code and shifts it left by 2. TLA's Trig_Sin was the asm2c
translation (right); the twin Trig_Cos ran GS1's Trig_Sin body on TLA's table: off the axes, cosine came out 4 times too
small (cos 0x100 = 16379 instead of 65516), on the axes right (its special case).

World Map: walking sideways eases the view's roll (the sprite's angle, +0x12 of the object's sprite, by 1/8 per frame
toward +-0x180; up eases it back to 0); Render_ApplyProjectedPlacement then builds the object's matrix with
AffineMatrix_BuildForEffect's rotation path (cos / scale): pa 49 instead of ~199, a ~5x picture in the 64 x 64
double-size box. Not drawing: the game wrote the bad matrix itself (gObjAffineMatrices[0]). Any rotated sprite was hit
the same way (the lighthouse cutscene's tumbling character; very likely the monks' turning heads, not reached by our
routes).

## Fix

`Trig_Cos` is a bind to `Port_TlaTrigCos` (port/tla/hw/pc_tla.c): `Trig_Sin(angle + 0x4000)`, TLA's own Trig_Cos
(adds a quarter turn, falls through into Trig_Sin), calling TLA's Trig_Sin (asm2c, D20 EQUIV 60). make_bindings.py's
BINDS has the row, pc.tsv's asm_small twins no longer list Trig_Cos. Trap 100.
