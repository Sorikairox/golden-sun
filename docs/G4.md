# G4 field notes (session GS4, 2026-11-01)

Status: **G3's exit met** (title screen and file menu, node and Chrome, from a save made in the game) and the
first G4 step: the prologue plays from the name entry into Vale on the stormy night, Isaac walks, the Pause

## What plays now

From power-on with a blank save (`tests/routes/prologue.keys`): logos, File Screen name entry, Isaac's house
(Dora wakes him, lightning flashes the palette, Kyle), outside in the rain with Dora and Kyle ("You can find your
way, can't you?" Yes), then free walking in Vale (scene ValePrologue, stage FLAG_VALE_STORM_SENT_TO_PLAZA).
Start opens the Pause menu; `tests/routes/first_save.keys` saves to file 1 ("Your game was saved.", frame
5170). Rebooting with that flash: Nintendo, Camelot, the title intro (Mt. Aleph, clouds, the sun's lens
sprites), the title with PRESS START and "(c)2001 Nintendo / CAMELOT"; Start: the File Screen's icon menu with
Continue. Same frames in muted headless Chrome (~58 fps, 0 console errors).

Compared by eye with the vendor's own pictures: `graphics/title/screen.png` (logo, peak, clouds, copyright:
match; ours adds the PRESS START prompt, `prompt.png`), `intro_clouds.png` (lavender clouds, blue sky: match).
The storm night is drawn with PALETTE_TINT_WARM (weather.c, Weather_StartLightning: the "dark" palette) and
lightning to PALETTE_TINT_PALE, which is why Vale looks yellow-green; the vendor has no picture of that scene, and
the palettes are computed by vendor C (not a port), so this is taken as right until an emulator comparison.

## Runtime fixes on the field path

1. **A vendor C routine copied to RAM to run** (`RamCode_Load(routine, Tile_BuildCellPictures, size)`, glyph_arm.c):
   in wasm its address is a function table index, so the DMA copied low wasm memory and no alias was made
   (`no function at 0x0300347c`). hw.c now maps a DMA source below 0x10000 to that function's ROM address
   (`Port_CodeGbaOf`, codemap.c), copies the ROM's bytes and aliases the copy.
2. **K&R calls with differing argument counts** (Import_ActorSetAnimation: two words, many scenes pass three;
   PauseMenu_RunFar(0) for a `()` function...): wasm-ld made those calls trap (START in the field: `unreachable`).
   link.py now sends every call of a `(...)`-declared function to a per-signature adapter `NAME$c<sig>` that
   converts word for word (extra words dropped, missing ones 0, as r0-r3 would carry them), and veneers whose
   callers' signature differs from the target's convert the same way. 0 linker warnings (was 8).
3. **_call_via_r3** (the HANDOFF trap): field_psynergy.c's `_call_via_r3(param, target)` relies on the routine's
   address being in r3; port/c_rules.tsv rewrites the declaration to four words and the call to pass `script`.
   Save_WriteSector calls `gProgramFlashSector` (our flash.c function, a table index) through it: call_via.c calls
   it with its own signature.
