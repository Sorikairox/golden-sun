# GS42: TLA Isaac joined the party on the Dehkan Plateau (session GS42, 2026-11-16)

User (iPhone, retrowser, saves attached): "Isaac is in my party when I am just in the Dekhan plateau at the beginning
of the game. I was chasing the mars djinn"; "load the save and move right to exit the current room and trigger a djinn
movement again. After the djinn movement, Isaac appears".

## Cause

Game flags 0-7 are the party members; flag 0 is Isaac. The Mars Djinni's third escape (Dehkan Plateau, overlay 0x655,
s27e0.c Func_020027e0, trigger 0x20) calls the asm routine Func_02002698(21, 25, 0x210) and later (24, 25, 0x216):
the routine plays the Djinni's hop and ends with GameFlag_SetBit(its third argument). Func_02002698 is declared K&R
(`void Func_02002698();`), so the call goes through link.py's call adapter `ov655_Func_02002698$cvoid_i32_i32_i32`,
and that adapter called the routine's asm2c wrapper as defined from the declaration: **no words**. r0-r2 arrived as
0 and the routine set flag 0. Isaac joined, and flags 0x210/0x216 were never set.

Found with a test-only build (a temporary c_rule trapping in GameFlag_SetBit when flag == 0, never committed): the named
wasm stack read GameFlag_SetBit <- a2c_ov655_0200a698 <- ov655_Func_020027e0 <- Scene_RunTouchOrExit.

## Fix

tools/wasm/link.py: a K&R call adapter whose target is an asm2c routine (directly or through a veneer) enters the
routine's wrapper with the caller's words and returns r0, as the GBA's `bl` does (the same rule as GS41's veneers).
Diff of the glue: 171 adapters now take this path. 20 of them used to drop words (e.g. ov655 Func_02002698, ov668
Func_020040ec, ov681 Func_0200495c, ov6a5 Func_02003a6c/02003c58, ov6ab Func_02000ae4/02001fcc, ov6ad Func_02002800,
ov6ae Func_020053e4, ov6b3 Func_02000244/0200084c, the shop's Func_08109ad8/08109cac), 35 returned 0 instead of r0
(Text_MeasureEntry, Text_DrawCharacterAtOffsetFar, HeapSlot_Release, FieldMessage_ShowAtActor in 16 overlays, ...);
the rest were already equivalent. port/tla/short_knr_allow.tsv: Message_Start's row is stale (its adapter now passes
the caller's five words; the sixth stack word is 0 as before) and is removed. GS1 has no asm2c routines: unchanged.
