## 1. The waterfall statue: (a), the wrong position, not a port bug

How the game chooses (vendor):
- The Psynergy menu asks Scene_HasFieldPsynergyTrigger(group) (psynergy.c), which is Scene_FindPsynergyTrigger(ANY, group).
  That one calls Field_FindNearbyPsynergyTarget(leader, group) and returns the scene's PSYNERGY_ON_ACTOR row only when the
  actor found is the row's actor. With no row the menu takes Ply's own path: "Use it on whom?" (the heal).
- The Exterior's row: `{ PSYNERGY_ON_ACTOR(ABILITY_PLY), ACTOR_WATERFALL_STATUE, CONDITION_ALWAYS,
  EVENT(MercuryLighthouse_PlyOpensWaterfallPassage) }`. So **Ply is the right Psynergy**, on actor 12 (the fifth placed
  actor: a blue statue at PIXELS(856), 0, PIXELS(216), the cell 53,13).
- Field_FindNearbyPsynergyTarget: the search range comes from gFieldEffect_TargetRangeByMode: **16 px for Ply** (also Frost,
  Lift, Carry, Growth; 32 for Move/Mind Read/Whirlwind/Douse/Halt; 48 for Force/Catch). An actor counts only when
  `distance < range` (whole pixels toward 0, sqrt of dx^2 + dz^2), within 8 px of height, and past 11 px within ~34 degrees of
  the facing rounded to a quarter turn.

Evidence (port_work/g25/p1, the GS24 scratch keys replayed):
- GS24's cast: the leader stopped at x 834.6 after its RIGHT keys (cell 52,13 but not against the statue): dx = 856 - 834.6
  = 21 px >= 16, so no target, so the heal path. That is exactly what the vendor code does.
- Holding RIGHT 55 frames longer the leader walks into the statue and stops at x 840.6, z 218.2 (actors probe: statue 856,216):
  dx 15, dz -2, distance 15 < 16. The same menu keys then cast Ply on the statue: the cast tint, the winged figures fly to
  the statue (p1/sheet.png). In the committed route the waterfall stops and the party rises (section 3).

Verdict **(a)**: the position. No port bug: no code or table pointer issue, no actor flag misread, no PORT_IS_CODE_INDEX case
(the actor test is a plain id compare). Trap 50 records the reach.

## 4. Saturos: checked against the vendor, game behaviour

- **His unit = enemy_table.c's row exactly** (bstat probe, read only): L18, HP 1200, PP 160, Atk 113, Def 35, Agi 51, Luck 40;
  elements (power/resistance V, Me, Ma, J) 100/100, 90/72, 110/175, 100/127 (preset 39); one action a turn; abilities Heat
  Flash, Fireball, Attack, Eruption.
- **One Fireball, every hit to the unit** (power 65, range 3, ABILITY_FORMULA_DAMAGE): Battle_CalculatePsynergyPower(65,
  110 - res) x gRangeFalloff_PsynergyDamage[distance] (100, 80, 60...) + Battle_Random & 3:
  Garet (centre, res 119): 65 x 191/200 = 62 -> **63** seen; Isaac (beside, res 86): 72 x 0.8 = 57 -> **57**; Ivan (beside,
  res 88): 72 x 0.8 = 57 -> **59**; Mia (two away, res 87): 72 x 0.6 = 43 -> **46**. All within the +0..3 random.
- **Why the party loses**: Saturos (Agi 51) acts before Mia (35), so her heals land after his hit; Fireball takes ~225 a turn
  against 433 party HP; the party deals ~100 a turn (Ray 33, Tundra ~53 against Mercury res 72, attacks 12-28, a dodge).
  Three full attempts (Djinn + summon + Frost/Ply, Djinn + Tundra every turn, an HP-aware bot) all ended with Saturos at
  800-970; a heal-heavy plan (Isaac's Cure Well on the weakest below half HP, Mia's Ply on the next, Garet's Djinni turn 1,
  Ivan's Ray or Defend) did best, Saturos at 438 once and 644-804 over five retries with the event's B taps shifted a few
  frames (the battle's random numbers follow the input timing). The party is Lv 10 (earlier sessions fled most battles). Game behaviour: the party needs levels.
- **Mia's endless PP** in the aerie: "Mia recovers 4 PP!" after each cast, as the aerie's Mercury light says.
- **Isaac's max HP drops 124 -> 115** after unleashing Flint: the Djinni goes to standby and his class changes. Game rule.
- **"Isaac summons Mercury" in one attempt, "Mars" in another**: the first Djinn list entry differs once a Djinni has
  recovered; the bot picks the first entry. Not a bug.
- **A party wipe wakes the party in Imil** (the last sanctum), only the leader at 1 HP: the game's rule (G19 3).
