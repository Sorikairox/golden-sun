# G2: everything compiles and links to one wasm (session GS2, 2026-11-01)

Run: `tools/web_build.sh` (stages ll, bind, obj, link, leak; `--only a,b` for some). It needs the reference
build of G1 for two inputs: `port_work/g1/gen/text/msg_ids.h` (message ids) and, for the overlay part of the
leak check, `port_work/g1/alchemy/overlays/*.bin`. Output in the gitignored `build/wasm/`.

## Result (exit criteria)

- **All 124 C code objects** of tbs-en (73 main image, the rest the 96 overlays and 3 debug overlays) compile
  to wasm and **link into one `game.wasm`** (1.7 MB; data section 3.4 KB). It instantiates and runs `main` in
  node: heap 0x00119fc0-0x01f00000, under the GBA regions.
- **42 logged stubs**: 23 vendor assembly routines still to port by hand (D6: Bios_CpuSet, Trig_Sin/Cos,
  Heap_Release, HeapSlot_Release, the m4a mixer and track commands, umul3232H32, __divsi3...), 15 PC-layer entry
  points (Port_DmaWritten, Port_Iwram*, Port_BiosHalt/Stop, Port_FrameWaitStackTop), 4 others. List:
  `build/wasm/stubs.tsv`. Plus **300 generated veneers** (far-call and overlay-import stubs) and 8 linker
  signature-mismatch warnings (K&R declarations whose callers pass other arguments; trap only if called).
- **Leak check passes**: 1,904,215 16-byte windows of the ROM's data (main image and uncompressed overlays)
  looked up in game.wasm, 0 found. No data object is compiled; 1,802 C definitions of game data are dropped.

## How

1. **Sources** (`tools/wasm/port_src.py`): `build/wasm/tbs` mirrors `games/tbs` with symlinks; only changed .c
   files are real files. Generic rules: GNU nested functions -> clang blocks with `__block` on every captured
   parent local (from clang's JSON AST; captured parameters are copied into `__block` locals); empty asm
   barriers lose ARM clobbers and Thumb `l`/`h` classes; other asm from `port/asm_rules.tsv`. 11 nested
   functions in 8 files, 6 asm statements in frame.c.
2. **IR**: clang --target=wasm32-unknown-emscripten -O2 -fblocks, `port/shim/prelude.h` first (D17).
3. **Binding** (`tools/wasm/bind.py`): with opaque pointers a data symbol is `ptr @name`; each becomes
   `inttoptr (i32 ADDRESS to ptr)` (ROM, RAM, overlay area, absolute id). Code-pointer tables and the data that
   points to them (closure over `port/symbols/relocs.tsv`: 416 symbols, 91 KB) become zeroed buffers to be
   filled from the ROM with patched pointer slots at run time (G3). Overlay definitions get `ovNNN_`.
4. **Link** (`tools/wasm/link.py`): veneers and stubs generated as IR with the callers' signatures; emcc with
   230400 KB of memory (0x0E100000), no growth, `--no-gc-sections`.
5. **Leak check** (`tools/wasm/leak_check.py`).

## Known gaps (G3 work)

  pieces (irq_table's unnamed parts) has no buffer name.
- 51 code labels are read as data (`build/wasm/code_as_data.tsv`): ARM routines the game copies into RAM and

  a copy needs a port routine.
- Main-to-overlay calls go through the overlay entry tables at 0x02008000 (function addresses as integers):
  needs the overlay dispatch of D7.
- Overlay static variables (59) live in wasm memory, not in the overlay area: check whether the game expects
  them zeroed on each overlay load.
