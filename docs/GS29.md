## 1. The floating "Settings" heading

The green "Settings" tab that bobs above the windows is the game's menu-title sprite pair (`MenuTitle_Create`, picture 7
of gMenuTitlePictures). In the vendor code GS1 draws it on **its own Change settings screen** (SettingsMenu_Run,
window/window/settings_menu.c: `MenuTitle_Create(7, settingsWindow, 64, -48)`), and the "Pause" heading (picture 6) on
its Pause menu. **Our** Extra settings screen (port/pc/options.c, GS27) also created it, to copy Change settings' look:
that one we added, so it is **removed** (1efad3f). The game's own headings on Change settings and the Pause menu stay.

"R: More" (GS27, on Change settings): a small ordinary window (Window_Create at tile 22,0, 8 x 3, the game's frame and
font), placed at the top right beside the game's heading and touching the help window below it. It is not a sprite, does
not bob and is not a heading: it does not float like the title. Left as it is.

## 2. Map zoom

**Levels** (in the game: Extra settings row "Map zoom" Normal / More / Most; page: select "Map zoom", key `gs-zoom` = 1 or 2,
nothing stored for Normal; test override `?zoom=0/1/2`):

| level | frame | scale | margins (each side) |
|---|---|---|---|
| Normal | 240 x 160 | 1 | none: the game as before |
| More | 288 x 192 | 1.2 | 24 px across, 16 px down (3 tiles, 2 tiles) |
| Most | 336 x 224 | 1.4 | 48 px across, 32 px down (6 tiles, 4 tiles) |

Why these: 3:2 with whole 8-px tiles on every side means 2 x margin-across = 3 x margin-down, so the down margin is a
multiple of 16: 16 and 32 give these two; the next (48) is 384 x 256, past what the GBA's 256-line OAM y can place
around the screen (and the hidden OAM entries at y 192 would sit inside it everywhere). A stored GS27 `gs-wide=1` becomes
`gs-zoom=1` (Wide view's 288 columns) once, and gs-wide is removed.

**What zooms**: field maps inside the field sequence (towns, dungeons, interiors), including the windows, dialogue and
full-screen menus opened over them (they are drawn the GBA's size in the GBA's area, so they look smaller). **What stays
240 x 160** (and fills the same box): battles, the World Map, the title and File Screen (also the File Screen after
Continue, which runs inside the field sequence), naming, credits, anything else.

**Renderer** (port/pc/ppu.c, the GS1 branch; TLA builds the other one, unchanged):
- The frame is LW x LH with the GBA's 240 x 160 at (XO, YO). Rows above it are drawn at line 0 with line 0's registers,
  rows below at line 159 with line 159's (hw.c's frame driver is unchanged).
- Map layers' margins (across and down, corners too) come from the map grid's cells in game RAM, as GS27 did; the check
  that a layer's BG map holds the grid's cells (its first and last columns on a line) is made on the GBA's lines.
- Sprites: OAM x wraps at 240 + the right margin; on margin rows a sprite is below the screen while its OAM y is under
  160 + the bottom margin, else above (the GBA's lines keep the GBA's rule). The OAM build's hidden entries
  (0x00C000C0 words: y 192, x 192, tile 0xC0) are skipped on margin rows (e434de5; they drew a stray tile at Most).
- The window layer (BG0) stays the GBA's 240 x 160; WIN0/WIN1 in the margins use the edge column / edge line.
- **Which frames**: inside the field sequence with a map scrolled this frame (GS27's stamps), and the previous such
  frame's map layers matched the grid on at least 80 of its lines (otherwise the File Screen after Continue zoomed). A
  frame entering the field is 240 x 160 once, then zooms.
- **The camera never moves** (game logic unchanged). New: the GBA's view is placed in the frame so that the frame stays
  inside the map's camera bounds (gMapGridWork minX/minY/maxX/maxY) wherever the map is at least the frame's size:
  near a map's edge the frame stops at the edge (like a camera clamp, presentation only) and the GBA's view sits
  off-centre in it, so there is no black margin at map edges any more. A map smaller than the frame (most interiors) is
  centred, black around it, as on the GBA. Pixels past the bounds are black as before.
- Culling follows the frame: `gPortZoomL/R/T/B` (pixels shown past each side this frame, all 0 at Normal and off the
  field) widen the field camera's actor test (actor_camera.c, across and down), Actor_GetScreenPosition (across only: it
  places message windows), and Sprite_Draw's right/bottom tests and its shadow's bottom test (c_rules). With all four 0
  every test is the original.

**Page** (port/web/main.js, index.html, touch.js): the canvas's box is fixed (CSS `width: min(100%, 720px)`, 3:2; touch.js
lays out a 3:2 box): it no longer depends on the frame. The frame is put into an off-screen canvas at its own size; the
visible canvas holds it times the smallest whole factor that covers the box's device pixels (nearest neighbour, so every
GBA pixel is the same size), and the browser smooths that slightly larger picture down into the box. This "sharp
bilinear" keeps edges crisp and avoids the uneven pixel widths plain nearest gives at 336 -> 720 (x2.14) or on phones;
at 240 -> 720 (x3) it is exactly the old picture. `window.GSScreen.src` is the frame before scaling (tests). The zoom
row is hidden on the TLA page (TLA's renderer has no zoom; GS27's Wide view checkbox showed there and did nothing).
