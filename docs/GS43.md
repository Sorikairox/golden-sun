# GS43: TLA crashed when a battle effect built a blitter from asm (Blitz) (session GS43, 2026-11-16)

User (iPhone, retrowser, screenshot): "I tried to use Blitz djinn and the game crashed": `Aborted()` from
Port_ResolveCode <- a2c_call <- a2c_dispatch <- a2c_0815f16c <- BattleEffect_DispatchByIdRange.

## Cause

Effects draw on the 128x128 canvas with blitters that Func_08196404 assembles as ARM code in a heap slot (here slot
47, IWRAM 0x03005380). asm2c cannot run those patched words, so the PC layer binds Func_08196404 to
Port_TlaBuildBlitter (port/tla/hw/pc_binds.tsv, TLA7): it runs the translation, then aliases the slot's address to
GS1's C blitter. C callers reach the binding; **asm2c's direct calls did not**: `bl Func_08196404` became
`a2c_08196404()`, the bare translation, so no alias, and Blitz's effect (Func_0815f16c, then `blx` through slot 47)
jumped to 0x03005380: "no function at GBA address 0x03005380". 41 asm call sites (battle effect routines) build
blitters this way. Not new: the GS41 build fails the same.

Found by reading the a2c register file at the abort (Emscripten onAbort, a scan of static memory for the saved lr):
the call returns to 0x08160cf2, r4 = *(0x030000bc) = heap slot 47.

## Fix

tools/wasm/asm2c.py: a routine pc_binds.tsv binds without `replace` (today only Func_08196404) is called by
translated code through the new a2c_call_port (port/tla/a2c/a2c_rt.c): Port_ResolveCode gives the port function,
called with r0-r3 and the stack words as a2c_call does for C code. The port function still runs the translation.
